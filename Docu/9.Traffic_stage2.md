# Stage 2: NMS commands the robot's Internet iperf3 client

These are incremental patches based on the uploaded October 22 sources, with
Stage 1 already applied on the robot. Do not apply the robot patch to the NMS,
or the NMS patch to the robot. No AP code, spreadsheet format, or CommonCheckers
rules change. Only Echo is selected initially; Internet mode stays disabled
until the NMS host setting is filled in.

## 1. Apply to Echo first

From /opt/_RunScanner, with robot_iperf3_client_stage2.patch copied there:

    git apply --check robot_iperf3_client_stage2.patch
    git apply robot_iperf3_client_stage2.patch
    python3 -m unittest discover -s tests -p test_robot_traffic.py -v

Expected: 10 tests pass. If --check fails, stop and provide the output and the
current versions of the files it names. Do not force application.

Robot files changed: robot_agent.py, robot_dispatch.py, common_nms.py,
robot_handlers_traffic.py, tests/test_robot_traffic.py. config.py already has
its Stage 1 additions, so this incremental patch does not change it.

## 2. Apply to the NMS

In the NMS repository root, use your existing Git terminal:

    git apply --check nms_iperf3_client_stage2.patch
    git apply nms_iperf3_client_stage2.patch

Files changed: config.py, m4Commands.py, m5Northbound.py, m7Traffic.py.
Files added: m7TrafficRemote.py, tests/test_m7traffic_remote.py.

In NMS config.py, set these newly added settings:

    TRAFFIC_SERVER_HOST: str = "ping.online.net"
    TRAFFIC_SERVER_PORTS = list(range(5200, 5210))
    TRAFFIC_REMOTE_SCANNERS = ["twin-scout-echo"]

The host defaults to blank in the patch, leaving original behavior intact.
Other robots keep the original NMS-client / robot-server operation until
explicitly included in TRAFFIC_REMOTE_SCANNERS and updated with both patches.
Port selection starts at different offsets for consecutive jobs; the server's
busy response arbitrates access, and the robot tries the remaining configured
ports only for that response. This does not reserve public-server capacity.

Restart the NMS and Echo's robot agent using your existing startup procedures.
Do this with no manual or registered traffic session running. No web-server
installation or configuration is involved. Production needs no new Python
package beyond the existing NMS/robot dependencies and iperf3.

## 3. One short manual test through the NMS

Open the NMS Swagger page, normally http://127.0.0.1:8000/docs on the NMS PC.
Choose POST /traffic/_enqueue, Try it out, and submit:

    {
      "scanner": "twin-scout-echo",
      "action": "traffic.session.start",
      "args": {
        "session_id": "SStage2",
        "protocol": "udp",
        "ac": "bk",
        "duration_sec": 20,
        "report_interval_sec": 5,
        "reverse": false,
        "bitrate": "5M",
        "packet_size": 1200
      }
    }

This is a short manual connectivity test, not a CommonCheckers-registered
experiment. Registered scripts retain their >60-second duration and 60-second
report interval rules.

Allow approximately one polling interval plus 20 seconds and result delivery
on a subsequent poll. Busy public ports may add delay. Use the new read-only
GET /traffic/_remote_result/{scanner}, with scanner=twin-scout-echo, to retrieve
the latest NMS-accepted result. It includes execution_id, timestamps, selected
server_port, attempts, status, Wi-Fi snapshots, and untouched raw iperf3 JSON.
The diagnostic snapshot is retained for 48 hours independently of the regular
northbound uploader. Check timestamps/session ID: it returns the latest result,
which could belong to the previous test while a new session is still running.

A successful test confirms NMS -> robot command delivery, busy-only retries,
robot -> NMS result return, and Redis acknowledgement. Then repeat with a new
session_id (for example SStage2Up) and reverse=true for robot upload. Save or
paste the GET output for review. The next registered experiment will verify
web/Data Lake interpretation and AP byte accounting; manual endpoint success
does not establish those yet.

To request an early stop, POST /traffic/_enqueue with:

    {
      "scanner": "twin-scout-echo",
      "action": "traffic.session.stop",
      "args": {"session_id": "SStage2"}
    }

Stops arrive through robot polling, so they are not instantaneous. A matching
running execution receives SIGTERM, then SIGKILL after three seconds if needed.
A scheduled start still in the NMS traffic queue can be cancelled by a stop.

## Direction and data ownership

Script reverse=false remains download to robot and becomes iperf3 -R.
Script reverse=true remains upload from robot and omits iperf3 -R.
Raw JSON keeps the actual iperf3 role values. Northbound records explicitly
include client_role=robot and iperf_reverse so consumers can distinguish them.
We have not inspected or modified the web backend's raw-result parsing.

The NMS retains experiment/session provenance when handing a job to the robot.
Redis Lua scripts make command handoff and result/event deduplication atomic.
The robot deletes pending files only after their specific IDs are accepted.
A failed request or unavailable Redis leaves the records pending for retry.
Earlier manual-test records with no corresponding NMS execution are moved to
traffic_state/rejected with a reason; their contents are preserved and they
are not attached to a new experiment.

AX210 IPv4 source binding remains enabled. The successful physical tests on
Echo established that binding works there; the patch does not change routing.
Requested AC/TOS and observed application categories remain distinct.

install fakeredis[lua] there and run:

    python -m unittest discover -s tests -p test_m7traffic_remote.py -v

No physical NMS/robot or real Memurai instance was used for these integration
tests. Live end-to-end deployment is the next check above.

## Stage boundary and rollback

Use this patch for short attended tests first. Recovery of active clients after
an agent crash/restart and stopping active clients via experiment deletion or
replacement are not implemented in this stage. Stop active sessions explicitly
and wait for their results before deleting/replacing an experiment. Redis
execution/dedup markers currently have no automatic pruning; a later retention
policy must keep them at least as long as robot retries remain possible.

To return Echo to its original traffic mode, finish/stop its active remote
session, set TRAFFIC_SERVER_HOST to an empty string, and restart the NMS. The
original robot iperf3 server services are unchanged and remain available. Keep
the updated robot agent running long enough to deliver pending remote results.
